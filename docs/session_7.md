- **F4 (carried):** braces/deepmerge-ts advisories — no upstream fix; the accepted-risk stance stands.
- **F5 (convention):** this file replaced the session-6 transcript.
- **Trap 7 (discovered, documented, accepted):** v4's opacity modifier (`/75`, `/50`, `/10`…) emits `color-mix(in oklab, …)` which Chrome serializes as `oklab(L a b / α)` — the reference's v3 emitted `rgba(r, g, b, α)`. Pixels are identical; the strings differ. The parity specs assert resolved channels (`expectInkAlpha`: exact alpha + bounded lightness) instead of strings, and the classes keep the reference's modifier syntax (class parity outranks string parity). This also revealed the login input's `bg-slate-50/50` had ALWAYS computed oklab in the clone — a session-6 verification blind spot (its "identical" claim measured pixels), now documented in the trap log.

**RED evidence:** `tests/first-sentence.test.ts` 5/5 failed (import error — the helper didn't exist); the new e2e specs failed 9/10 against the unremediated build (the one passing spec was the refund regression-guard, green on both sides by design). **GREEN:** all new specs pass after the fixes; two spec-side shapings were needed mid-run (the trap-7 oklab channel idiom replacing rgba-string assertions, and the trap-4 margin-side swap for space-y assertions — both following the established mobile-navigation precedents).
