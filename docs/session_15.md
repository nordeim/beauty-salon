## The instrument lessons (recorded in SKILL v1.12.0 + PAD)

**Navigation-policy parity is invisible to every census that reads the DOM at rest** — the settled DOM, the href census, and the class census all pass identically while the router's scroll/hash policies diverge on interaction; each needed its own interaction instrument (programmatic scroll + link click + `scrollY` reads; hash-link dispatch + URL/history reads). The census itself carried three traps, each defused in the spec:

1. **The asynchronous smooth restores** — both sites set `html { scroll-behavior: smooth }`, so the popstate restores animate (the clone's: 141 → 1971 → 2000 over ~2.6s); snapshot reads catch mid-flight values. The specs read SETTLED values via `expect.poll` (the settled-state read convention).
2. **The false-green clamp-cancel** — an origin EXCEEDING the target page's max scrollable (a 3000-origin variant) lets the route-swap's clamp cancel the mid-flight reset, transiently passing a polled assertion. The final spec uses the live census's own 2000 origin (below the services max at the e2e viewport — no clamp masking) with settled direct reads.
3. **The scrollIntoView origin-destruction** — Playwright's actionability `scrollIntoViewIfNeeded` smooth-scrolls to the clicked element BEFORE clicking; for a CTA above the scrolled origin it destroys the very offset the contract pins (the measured "2000 → 63 anchoring" was exactly that mid-flight origin, not app behavior). The deep-link contract clicks via a dispatched event; verified on the production build with a settled origin, the clone clamps CLEANLY to max (423) exactly like the live (427) — an `overflow-anchor: none` rule trialed against the "anchoring" was REMOVED once the artifact's true cause was found (the app's settled-origin behavior was already at parity without it).
