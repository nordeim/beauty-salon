## Findings and the TDD fixes

All six actionable findings fixed per the plan across 3 files + 3 spec files:

- **The confirmation page** (`src/app/book/confirmation/page.tsx`): `Flower2 strokeWidth={0.5} className="h-64 w-64 md:h-96 md:w-96"` replaces the CalendarPlus watermark (the `Calendar h-4 w-4` on the button is untouched); the circle gains `style={{ opacity: 0 }}` (settled invisible, element + classes kept for DOM parity); the policy link becomes the `/contact` route link with `underline hover:text-foreground inline-flex items-center gap-1` + the trailing `ArrowRight h-3 w-3`. The settled-state rule applied: replicate runtime inline styles when they change computed behavior; skip inert ones (the watermark wrapper's settled `opacity: 1; transform: none` matches the defaults — omitted like the trailing-space artifacts).
- **The landing hero** (`src/app/(site)/page.tsx`): the parent gains `style={{ opacity: 1, filter: "blur(0px)", transform: "none", scale: "none" }}` and the img `style={{ transform: "scale(1.08)" }}` — the box now renders 457×610 @1280 / 366×488 @390, exactly the reference.
- **The category images** (`src/app/(site)/page.tsx`): `object-cover transition-transform duration-s] group-hover:scale-110` — the reference's corrupted token kept inert (computed 150ms default ease both sides), the dead-on-live `ease-[…]` token dropped (it WOULD generate in the clone's v4 and change the computed timing).
- **The head layer** (`src/app/layout.tsx`): metadata gains `icons: { icon: { url: "/images/logo.png", type: "image/svg+xml" } }` + `manifest: "/manifest.json"`.

**TRAP 8 discovered mid-GREEN (the session's headline engine finding):** the first hero fix replicated the reference's settled inline `transform: none` verbatim — and the box *still* measured 572px while `getComputedStyle().transform` read `none` and `offsetWidth` read 457. Root cause: **v4's `scale-125` writes the individual CSS `scale` property (`scale: 1.25`), not `transform`** — so a v3-era inline `transform: none` does not neutralize it (the rect includes the individual-property scale; offsetWidth does not). The v3 reference's `transform: scale(1.25)` → framer's `transform: none` neutralization does not map 1:1 onto v4. The fix adds `scale: "none"` alongside (React 19 supports individual transform properties as style keys). Corollary documented the same way: v4's `transition-transform` transitions `transform, translate, scale, rotate` where v3 transitioned `transform` (caught by the category spec's property assertion mid-run). Trap 8 is now registered in all five docs' trap logs.

**RED evidence:** the new specs failed **7/7 actionable groups** exactly as the plan predicted (the flower2 glyph, the circle opacity, the policy link, the favicon, the manifest, the hero settled box, the category hover timing) while all four regression guards stayed green (Calendar icon, innerText 536, the favicon asset, the gallery tiles' 700ms + the 10 pre-existing landing tests). **GREEN:** 21/21 after the fixes + two spec-side shapings, both documented in the spec comments: (1) the sage/30 watermark color serializes as `oklab(L a b / 0.3)` on the clone vs the reference's v3 `rgba(75, 93, 79, 0.3)` — the trap-7 pattern applied (`expectSageAlpha30` asserts the resolved channels, like `expectInkAlpha`); (2) Chrome reports `text-underline-offset` as the used keyword `auto`, not a resolved `0px`.

## The lesson (recorded in SKILL v1.7.0 + PAD)

**Two more DOM layers were structurally invisible to every existing instrument.** The **head layer**: every parity instrument reads `document.body` — the favicon (the one browser-visible head element) never appeared in any innerText or computed-style read, so nine green sessions shipped without it. The **settled-state transform layer**: the reference's animation framework writes runtime inline styles that override its own classes at rest — both sites carry `scale-125` in the class attribute (class-string comparison: equal), but the effective boxes differ by 25%; only a settled-state both-sides `getBoundingClientRect`/computed read reveals it. This extends the session-9 lesson (every DOM layer text comparisons flatten needs its own census + spec) with a sharper corollary: **class-parity is not behavior-parity when a runtime framework rewrites the style layer — assert the settled computed state, not the class list.** And trap 8 is the engine-level twin: even a faithfully replicated v3 neutralization (`transform: none`) does not produce the same computed result under v4's individual-transform properties.
